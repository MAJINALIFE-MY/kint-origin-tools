# 開発用スキルの同期

本体の初回配置・同期エラー・方式の変更時に読む。ドメインのinit/updateとは別の処理。

- AGENTS.mdと `.agents/skills/` が正本。Codex・Cursorはこれを使い、ClaudeはCLAUDE.mdのimportと `.claude/skills/` の生成配置を使う。
- `.agents/dev-config.json` のskills/rolesに登録したものだけを同期する。役割は現在空。追加時は `.agents/roles/` と登録を揃える。
- `npm run agents:sync` は標準でスキルごとのリンクを作る。Windowsはcheckout内のjunction、ほかのOSは相対symlink。生成リンクはGitへ収録しない。
- リンクを作れない初回は `npm run agents:sync -- --copy` を使う。scripts/references/assetsもコピーする。コピー先はローカル生成物。
- `.agents/generated.json` は管理対象・直前の生成内容・方式の台帳。追跡する。台帳を消して独自変更検出を回避しない。
- `agents:check` は同期状態に加え、本体と配布スキルの参照を検査する。`agents:test` は隔離fixtureで同期・独自変更保護・参照検査の失敗例を確認する。

## 競合・削除・方式変更

1. agents:checkの対象と差分を確認する。生成物の独自変更を正本へ取り込むか別の場所へ保全する。
2. 正本と旧配置の対応を確認し、問題のあるローカル生成物だけを取り外す。リンク先の正本を再帰削除しない。
3. 方式変更では管理済み配置と台帳を保全してから旧生成先を取り外し、新方式で同期する。スクリプトは方式やディレクトリを自動で一括変更しない。
4. スキル削除・改名でも旧生成物は自動削除されない。個人設定・未登録のファイルは維持する。
5. 再同期後にagents:checkとagents:testを通す。

## クライアント上での確認

各クライアントのスキル一覧で3スキルの名前・パス・重複を確認する。リンクと正本の管理UI上の二重表示と、実行候補の登録を区別する。
開発・検証・設定変更の依頼で対応するスキルが選ばれることも確認する。個人の第三者設定取り込み等は、ほかのプラグインに影響するため自動変更しない。
