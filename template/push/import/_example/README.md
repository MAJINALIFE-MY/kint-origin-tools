# 更新キー付き CSV 取込の書き方（_example）

このフォルダは `kint-origin push import` の**雛形**です（`_` 始まりのフォルダは実行対象外）。
kintone の「ファイルから読み込む」と同じく、**1 行 = 1 レコード、列名 = フィールドコード**の CSV を、更新キーで照合して**一致すれば更新、無ければ追加**します。
使うときは、このフォルダを `push/import/<ジョブ名>/` にコピーして `import.json` と `records.csv` を編集してください。

```
push/import/社員取込/
  import.json  # 必須。取込先のアプリと更新キー
  records.csv  # 必須。ヘッダー = フィールドコード。UTF-8（BOM 可）。Shift_JIS なら import.json に "encoding": "sjis"
  runs/        # kint-origin が書く実行記録（プレビュー・バックアップ・結果）。編集しない。コミットされない
```

`records.csv` と `runs/` は雛形の Git 除外対象ですが、`import.json` は除外されません。対象アプリや顧客データを含むため、このフォルダ全体を公開しないでください。

## 手順

1. `kint-origin show records --id 123 --limit 5` などで、フィールドコードと現在の値を確認する（読み取りのみ）。
2. `import.json` と `records.csv` を編集する。
3. `kint-origin diff import --name <ジョブ名>` で検証する（API は GET のみ。更新・追加の件数と変更前後が `runs/<時刻>-diff/preview.csv` に出る）。
4. 内容を確認して `kint-origin push import --name <ジョブ名>`（y/N 確認あり）。**運用環境のレコードが即時に書き換わる**（動作テスト環境は無い）。
5. 戻す場合は `kint-origin push import --name <ジョブ名> --restore <実行時刻>`（実行時刻は `runs/` のフォルダ名。この実行で追加したレコードは削除される）。

`.env` の `KINT_ORIGIN_ALLOW_PULL_RECORDS=true`（読み取り・diff）と `KINT_ORIGIN_ALLOW_PUSH_RECORDS=true`（push）が必要です。PUSH_RECORDS は `push records` と `push import` の両方を許可します。

## import.json

| キー | 意味 |
| --- | --- |
| `app` | 必須。取込先のアプリ ID |
| `updateKey` | 必須。更新キーのフィールドコード |
| `encoding` | 任意。`"utf8"`（既定）／`"sjis"`（Excel の「CSV」で保存したファイルなど） |
| `guestSpaceId` | 任意。ゲストスペースのアプリのとき。無ければアプリ索引（`pull index`）から判定する |

## 更新キー

トップレベルの次のいずれかだけです（それ以外は `diff import` でエラーになります）。

- **レコード番号** — CSV の値は数字、またはアプリコード付き（`CODE-数字`）。一致しない行は新規追加で、番号はサーバーが採番する。
- **「値の重複を禁止する」を設定した文字列（1行）または数値**。

更新キーの列は必須で、値が空の行や、CSV の中で更新キーが重複する行はエラーです。環境側で 2 件以上一致してもエラーです。

## 値の書き方

- **CSV にある列だけ**を書きます。無い列は更新せず、現状を残します。
- **空のセルはフィールドを空にします**。ラジオボタンと必須フィールドは空にできないため、行番号つきでエラーになります。
- 値が今と同じフィールドはプレビューと送信から外れます。変更も追加も無ければ何も送りません。
- 複数の値（チェックボックス・ユーザー選択など）は、セル内を改行で区切ります。
- 日付は `YYYY-MM-DD`、時刻は `HH:MM`、日時は `2026-11-03T10:15:00Z`、数値は半角数字（`1000` や `-1.5`）で書きます。
- テーブル・添付ファイル・計算・ルックアップのコピー先・自動計算の列は取込できません（黙って飛ばさず、列を外すようエラーになります）。テーブルや添付は `push records` のジョブ CSV で扱います。

同じ `import.json` と `records.csv` の再実行は、反映済み・一部反映・結果不明・実行中の記録があると、API を呼ぶ前に止まります（内容を変えれば別のジョブとして扱います）。
