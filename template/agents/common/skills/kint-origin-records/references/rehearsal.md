# フォーム変更後の手動CSV確認

フォーム変更後の一連の確認に使う。更新キー付き取込は [CSV取込仕様](import-csv.md)、操作の承認は [push](../../kint-origin-push/SKILL.md) を参照する。

## 使う流れ

1. `pull app --id <appId>` と `pull records --id <appId>` で、編集前のフォームとレコードを取得する。`records.csv` と同時に `.kint-origin-records-schema.json` が作成される。
2. `data/.../form/fields.json` を編集し、`diff app --id <appId>` で設定差分を確認する。
3. フォーム画面で確認する必要があるときは、利用者が `PUSH_APP` を一時的に許可して `push app --id <appId> --no-deploy` を実行し、確認後に許可を戻す。CLIのレコード取得・書込コマンドに動作テスト環境はなく、レコードを運用環境へ直接書き込むコマンドは実行しない。
4. `diff rehearsal --id <appId> [--import <ジョブ名>]` を実行する。ローカルの取得物だけを使い、`.env`、認証情報、API、操作許可は使わない。`report.json` の `warnings`・`warningDetails`・`issues` と件数を確認する。
5. 新フォームが公開済みの別の検証用アプリで `baseline.csv` を新規追加として読み込む。列の対応、必須欄、更新キーを確認してから、指定した場合は `changes.csv` を更新・追加として読み込む。ベースラインにキーの空欄がある場合は、画面で検証用アプリの更新キーを確認してから進める。

## 出力

生成物は `push/rehearsal/<appId>/` に置かれ、`.gitignore` で除外される。

- `baseline.csv` は取得時と現フォームの型が一致する値を引き継ぐ。追加列は空欄になり、型変更・取得時の型不明・取得CSVに列が無い項目も値を引き継がない。削除列、添付、テーブル、レコード番号など取込非対応フィールドは出さない。
- `changes.csv` は既存の `push/import/<ジョブ名>/records.csv` を現フォームに照らし、画面取込用に変換する。チェックボックスと複数選択は選択肢ごとの列に展開する。更新キーは重複禁止の文字列または数値を使う。レコード番号をキーにするジョブは、この手順では生成できない。
- `report.json` は列状態、除外列、警告、問題、出力CSVのSHA-256を記録する。セル値や更新キーの実値は記録しない。

出力CSVを手編集すると、次の生成時に上書きが拒否される。必要ならコピーを作って編集する。既存の生成記録がないファイル、手編集されたファイル、入力取得後に `records.csv` が変わった場合は上書きせず停止する。CSVの生成に問題があるときも、可能なら `baseline.csv` と `report.json` を出して終了コード1を返す。

レコード番号を更新キーとするジョブは、対象アプリの公開済みフォームで `diff import --name <ジョブ名>` を使って確認する。別アプリではレコード番号が一致しない。
