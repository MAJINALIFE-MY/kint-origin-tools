# 更新キー付きCSVの入力仕様

作成・編集前に読む。承認・実行・復旧は [recordsスキル](../SKILL.md)。

## 更新キー付き CSV の一括取込（diff / push import）

kintone の「ファイルから読み込む」に相当する取込です。**1 行 = 1 レコード、列名 = フィールドコード**の CSV を、更新キーで照合し、**一致すれば更新、無ければ追加**します。job.csv（1 行 = 1 フィールドの操作。アプリ間のコピー・添付・テーブル行）とは別のコマンドで、**job.csv では更新キーによる上書き・追加はできません**。

> **`push import` も運用環境のレコードを即時に書き換えます**（動作テスト環境はありません）。実行前に必ず `diff import` で件数と変更前後を確認し、復旧の手順を把握してから実行してください。

書き込みは cli-kintone の `record import` ではなく、`push records` と同じ REST の bulkRequest（1 回 20 リクエスト・1 リクエスト 100 件。1 回は原子的）です。バックアップ・検証・復旧も同じ仕組みで、確認時の `revision` を送るため、確認後に他の人が更新したレコードは失敗します。

### 必要な許可（.env）

| コマンド | 必要な許可 |
| --- | --- |
| `diff import` | `KINT_ORIGIN_ALLOW_PULL_KINTONE=true`（既定）と `KINT_ORIGIN_ALLOW_PULL_RECORDS=true` |
| `push import`（`--restore` を含む） | `KINT_ORIGIN_ALLOW_PULL_RECORDS=true` と `KINT_ORIGIN_ALLOW_PUSH_RECORDS=true` |

### ジョブのフォルダ

```
push/import/<ジョブ名>/
  import.json   # 取込先のアプリと更新キー
  records.csv   # ヘッダー = フィールドコード。UTF-8（BOM 可）。Shift_JIS は import.json に "encoding": "sjis"
  runs/         # kint-origin が書く実行記録（プレビュー・バックアップ・結果）。編集しない。コミットされない
```

`push/import/_example/` は雛形です（`update` で最新化されます。ユーザーのジョブは温存されます）。入力の `records.csv` は雛形の `.gitignore` で除外されますが、`import.json` は除外されません。どちらも共有する前に内容を確認してください。ジョブ名の規則は `push/records/` と同じです。

`import.json`:

| キー | 意味 |
| --- | --- |
| `app` | 必須。取込先のアプリ ID（正の整数） |
| `updateKey` | 必須。更新キーのフィールドコード |
| `encoding` | 任意。`"utf8"`（既定。BOM 可）／`"sjis"`。読めない文字があれば、`encoding` の指定を案内してエラー |
| `guestSpaceId` | 任意。ゲストスペースのアプリのとき。無ければアプリ索引（`pull index`）から判定する |

不明なキーは（打ち間違いを防ぐため）エラーです。`records.csv` の行番号は、ヘッダーを 1 行目として数えます（job.csv と同じ）。

### 更新キー

トップレベルの次のいずれかだけです。それ以外（テーブル内のフィールド、「重複を禁止」でない文字列・数値、日付など）は `diff import` でエラーになります。

- **レコード番号**: CSV の値は数字、またはアプリコード付き（`CODE-数字`）。照合は `$id` で行い、値は書き込みません。一致しない行は新規追加で、番号はサーバーが採番します（`diff import` の `warnings` に件数を出します）。アプリコード付きの値があるときは、アプリのコードと一致しなければエラーにします（別のアプリの CSV の取り違えを防ぐため）。
- **「値の重複を禁止する」を設定した文字列（1行）または数値**。数値は表記の違い（`010.50` と `10.5`）を同じキーとして扱います。

更新キーの列は必須です。値が空の行、CSV の中で更新キーが重複する行はエラーです。環境側で同じ更新キーに 2 件以上一致するときもエラーです（更新するレコードを決められないため）。環境のレコードの更新キーが CSV のどの行とも完全一致しないとき（検索が大文字小文字などを同じ値として扱った場合）もエラーにします。

照合は `in (...)` で 100 件ずつ（URL が長くなりすぎないよう、値の長さでも分割）行い、文字列は kintone のクエリ用に `"` と `\` をエスケープします。

### 取込のルール

- **CSV にある列だけを書きます。** 無い列は更新せず、現状を残します（新規追加の行は、その列を送らないので既定値になります）。
- **空のセルはフィールドを空にします。** ラジオボタンと、必須で空にできないフィールドは、行番号つきでエラーです。
- 値が**今と同じ**フィールドは、プレビューと送信から外します（数値は桁の表記の違い、チェックボックスは順序の違い、日時は表記の違う同じ時刻を、同じ値として扱います）。**変更も追加も無ければ、何も送らずに終了します**（`nothingToDo: true`。実行記録も作りません）。
- 複数の値（チェックボックス・複数選択・ユーザー選択など）は、セル内を改行で区切ります。値の書式は job.csv の `set` と同じです（日付 `YYYY-MM-DD`・時刻 `HH:MM`・日時 `2026-11-03T10:15:00Z`・数値は半角数字・選択肢は名前）。セル内の改行は LF に正規化します（文字列（1行）は改行不可）。
- **テーブル・添付ファイル・書き込めない型の列は、黙って飛ばさずエラーにします**（計算・ルックアップのコピー先・自動計算・作成者・更新者・作成日時・更新日時・ステータスなど。この列を CSV から外します）。初回は通常フィールドだけが対象です。テーブルや添付は job.csv（`push records`）で扱います。
- 新規追加の行で、必須なのに既定値も CSV の列も無いフィールドがあれば、行番号つきでエラーです。
- 検証は、ファイル（`import.json`・CSV の構文）→ 列と値 → 環境のレコードの照合、の順で、各段階の問題は行番号つきでまとめて報告し、何も変更しません。

### diff import の読み方

`kint-origin diff import --name <ジョブ名>` は GET だけを呼びます。結果の JSON は [結果の読み方](../../kint-origin-commands/references/results.md) を参照してください。`runs/<時刻>-diff/preview.csv`（UTF-8 BOM 付き。Excel で開けます）の列は次のとおりです。変更のあるフィールドだけを 1 行ずつ出し、変更なしの行は出しません。

| 列 | 意味 |
| --- | --- |
| `line` | `records.csv` の行番号（ヘッダーを 1 とする） |
| `action` | `update`（更新）／`create`（新規追加） |
| `record` | 更新するレコードの ID。新規追加は `(新規)` |
| `key` | 更新キーの CSV の値 |
| `field` | フィールドコード |
| `before` / `after` | 変更前（新規追加は空）と変更後の値。複数の値は改行区切り |

`atomic: false`（一括処理が 2 回以上）のときは、途中で失敗すると前の回までは反映済みになります（`--restore` で戻せます）。
