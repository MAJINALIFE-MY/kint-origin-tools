# ジョブCSVの入力仕様

雛形はドメインの `push/records/_example/`。作成・編集前に読む。実行・承認・復旧は [recordsスキル](../SKILL.md)。

## job.csv

UTF-8（BOM は有無どちらでも可）で保存してください。**Excel の既定（日本語 Windows の「CSV」）は Shift_JIS で保存されるため、フィールド名が文字化けします**。「CSV UTF-8」で保存するか、テキストエディターを使います。1 行目はヘッダーです。**1 行 = 1 フィールドの操作**で、`op` が `#` で始まる行と空行は無視されます。

```csv
op,from_app,from_record,from_field,to_app,to_record,to_field,mode,value,note
copy,303,12,添付資料,450,7,資料,append,,旧アプリの添付を追記
copy,303,12,顧客名,450,7,取引先名,,,値の転記
set,,,,450,7,移行状況,,移行済,固定値
clear,,,,450,8,資料,,,添付をすべて外す
copy,303,15,添付資料,450,new:a,資料,,,新規レコード a に添付
set,,,,450,new:a,取引先名,,株式会社サンプル,新規レコード a の値
copy,303,12,明細[5039].金額,450,7,明細[new:r1].金額,,,テーブルに行を追加
set,,,,450,7,明細[5040].備考,,確認済,既存の行を更新
```

エラーに出る「行 N」は、**CSV のレコード（行）の通し番号**です（ヘッダー行が 1 行目です）。空行は数えず、値の中に改行があっても 1 行と数えます。そのため、エディターに表示される行番号とずれることがあります（空行や、値の中の改行があるとずれます）。

### 列

| 列 | 意味 |
| --- | --- |
| `op` | `copy`（別のレコードの値をコピー）／`set`（`value` を設定）／`clear`（空にする） |
| `from_app` `from_record` `from_field` | `copy` のコピー元（アプリ ID・レコード ID・フィールド）。`set` / `clear` では空にする |
| `to_app` `to_record` `to_field` | 書き込み先。`to_record` は**既存のレコード ID**か `new:<キー>`（新規レコード。キーは英数字・`_`・`-`、40 文字まで。同じキーの行は同じ新規レコードにまとまる） |
| `mode` | 添付とテーブル全体にだけ指定できる。`append`（既定。既存を残して追記）／`replace`（既存を置き換える）。それ以外のフィールドに指定するとエラー |
| `value` | `set` の値（`copy` / `clear` では空）。前後の空白も値として扱う。複数の値は改行区切り（CSV では引用符で囲む） |
| `note` | メモ（任意の列。処理には使わない） |

- ID はすべて正の整数です。**存在しないレコード ID は新規作成されず、エラーになります**（新規作成は `new:<キー>` だけ）。
- ヘッダーの列名が重複していると、後ろの列の値が使われます。列名は 1 回ずつにしてください。

### フィールドの書き方

- 通常: フィールドコード（例: `資料`）。テーブル**全体**を指すときもテーブルのコード（`明細`）です。
- テーブルのセル: `テーブル[行ID].フィールド`（例: `明細[5039].金額`）。行 ID は `show records` の `id` で確認します。
- 新しい行: `テーブル[new:<キー>].フィールド`（`to_field` のみ。同じレコード・テーブル・キーの行は 1 行にまとまります）。新規レコード（`new:`）のテーブルには、既存の行 ID は指定できません。

### `set` の値の書式

| 型 | 書き方 |
| --- | --- |
| 文字列（1行）・（複数行）・リッチエディター・リンク | そのまま（1 行は改行不可） |
| 数値 | `1.5`（`1,5` や単位付きは不可） |
| 日付 / 時刻 / 日時 | `2026-11-03` / `10:15` / `2026-11-03T10:15:00Z` |
| ドロップダウン・ラジオボタン | 選択肢の名前（存在するもの） |
| チェックボックス・複数選択 | 選択肢の名前を改行区切り |
| ユーザー・組織・グループ選択 | コードを改行区切り |
| 添付ファイル | ジョブフォルダからの相対パス（改行区切り。例: `files/契約書.pdf`）。絶対パスと `..` は不可、1 ファイル 1GB まで |
| 作成者・更新者・作成日時・更新日時 | **新規レコードだけ**（ユーザーのコード／日時） |

### `copy` できる型

- 同じ型どうし（ユーザー選択などは、コードだけを書き込みます）。選択肢系は、コピー先に同じ名前の選択肢が必要です。
- ドロップダウン ⇔ ラジオボタン、チェックボックス ⇔ 複数選択（選択肢の名前が一致すること）。
- 文字列（1行）・（複数行）へは、文字列・数値・計算・レコード番号・日付・時刻・日時・ドロップダウン・ラジオボタン・リンク・ステータス、チェックボックス・複数選択・カテゴリー（連結）、ユーザー・組織・グループ選択・作成者・更新者・作業者（表示名を連結）から。複数行の値は 1 行へはコピーできません。
- 数値へは、計算・レコード番号から（数字だけのとき）。
- 添付 → 添付（ダウンロードして再アップロードします。コピー元のファイルは削除せず、コピー先のappend/replace指定に従います）。
- テーブル → テーブル（テーブル全体のコピー。**内側のフィールドは、コードが同じものどうしを対応付けます**。コピー先に無い・書き込めないフィールドは対象外、コピー元に無いフィールドは空になります）。
- 上記以外はエラーです（`型 X から Y へはコピーできません`）。

### 書き込めないフィールド

計算、レコード番号、ステータス、作業者、カテゴリー、関連レコード一覧、ルックアップの**コピー先**フィールド、自動計算が設定された文字列（1行）、ラベル・スペース・罫線・グループ。作成者などは、既存レコードには書けません。ラジオボタンと必須フィールドは `clear` できません。

### 同じセルへの複数の書き込み・新規レコード・テーブル

- 同じレコードの同じセルへ複数行で書くとエラーです。**例外**: 添付への `append`（`copy` / `set`）どうしは、行の順に合成されます。テーブル全体の `replace` / `clear` は、同じテーブルへの他の操作と併用できません。
- 新規レコードは、必須フィールドで既定値が無いものをジョブで指定します（無いと `diff records` が行番号つきで報告します）。
- **テーブルは、行 ID を指定した行のセルだけを更新します**（指定しないセル・行は変わりません）。`append`（既定）のテーブル全体コピーは既存の行を残して行を追加、`replace` は既存の行をすべて消してコピー元の行にする、`clear` は全行を削除します。

ジョブ名は文字・数字・ハイフン・アンダースコア・ドット（先頭は文字か数字、100文字まで）。Windows予約名は使わない。
プレビューCSVの列は `to_app,to_record,to_field,op,mode,before,after,source,rows`。

検証は構文→フィールド・型・値・添付・重複→レコード・テーブル行・必須の順。長さ・数値範囲・ユーザーコードの実在・日付の妥当性などはサーバーが検証する。
